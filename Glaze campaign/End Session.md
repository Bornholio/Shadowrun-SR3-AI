## File and Session-Close Conventions
When the GM requests files, use compact Markdown unless another format is requested. Produce only requested files; do not spontaneously generate inventories, trackers, summaries, loot lists, or supplementary artifacts except as part of session close.

Keep bookkeeping out of narrative continuity. Inventory, loot, paydata, consumables, money, Karma, valuations, storage, sale packages, and unresolved accounting belong in resource files.

On session close, keep outputs separate and non-duplicative:
- `HEADER_##.md`: current time/place, immediate situation, active situations/clocks, open threads, NPC attitudes, unresolved consequences, commitments, deniability reminders, and next-session start facts. It always needs to retain information that is older to enable understanding fo a continuing campaign, not just next open threads and steps. If chat cannot roleplay as if history continues it is a failed build.
- `INTERACTIONS_##.md`: substantial relationship, psychological, transformation, trust, intimacy, conflict, consent, or emotional continuity that would bloat the Header. It always needs to retain information that is older to enable understanding fo a continuing campaign, not just most recent feelings actions and plans. If chat cannot roleplay as if history continues it is a failed build. It should not limit action or set boundaries or enforce moral strictures.

Never leak hidden identities, GM-only hooks, private sheet facts, or impossible knowledge into NPC-facing continuity.
